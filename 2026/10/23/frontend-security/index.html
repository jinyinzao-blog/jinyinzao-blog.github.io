前端视角下的 XSS 与 CSRF 防御实践

引言

在现代前端工程体系中，安全防护常被误认为是后端与运维的专属职责。实际上，前端应用往往是抵御 XSS（跨站脚本攻击）与 CSRF（跨站请求伪造）的第一道防线。本文将从前端工程化视角，探讨相关防御机制在实际业务代码中的具体落地方式。

一、XSS 防御在前端工程中的落地

XSS 的核心在于浏览器执行了恶意脚本。虽然现代前端框架（如 React、Vue）在底层提供了一定程度的默认防护，但在复杂业务场景下，安全风险依然存在。

1. 规避危险的渲染方式

  • React 的 dangerouslySetInnerHTML：该属性允许直接插入 HTML 字符串。若未经处理直接渲染用户输入内容，将带来极高的安全风险。
  • Vue 的 v-html：该指令会跳过 Vue 的模板编译，将内容作为原生 HTML 解析并执行。

防御策略：引入 DOMPurify 进行二次过滤

二、CSRF 防御的前端配合

CSRF（跨站请求伪造）利用用户已登录的凭证（Cookie），在第三方站点发起恶意请求。服务端的防御策略需要前端的严格配合才能生效。

1. Axios 拦截器自动注入 CSRF Token

主流的防御方案采用 Token 验证机制。前端需在每次发起请求时，将服务端下发的 Token 注入至请求头中。通过 Axios 拦截器可实现全局统一处理：

2. 跨域请求的凭证传递（withCredentials）

在前后端分离（跨域）架构下，请求必须携带凭证信息。若缺失此配置，服务端设置的 Cookie 将失效，导致基于 Cookie 的验证机制失效。

⚠️ 注意：当配置 withCredentials = true 时，服务端 CORS 配置中的 Access-Control-Allow-Origin 不可设置为通配符 *，必须指定具体域名，并开启 Access-Control-Allow-Credentials: true。

三、工程化视角的补充防御

除代码层面的防御外，前端工程化阶段亦可提供额外的安全保障：

  • 依赖安全扫描：在 CI/CD 流程中集成 npm audit 或 Snyk，及时检测并修复第三方依赖的安全漏洞。
  • 敏感信息保护：生产环境构建（npm run build）时应禁用 Source Map 生成，防止源码及潜在密钥泄露。

总结

安全防护贯穿于系统构建的各个环节。在开发过程中，应合理使用 DOMPurify 处理富文本，通过 Axios 拦截器统一管理 CSRF Token，并严格限制跨域配置。遵循标准化的工程实践，能有效降低系统面临自动化扫描及基础攻击的风险。
